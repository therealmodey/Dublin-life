# Lagos Life map rendering findings

**Scope:** source-level investigation of the saved public JavaScript references for the Lagos scene and Abuja map, with a few performance-oriented mechanisms relevant to the clone. This documents code paths, not measured frame rates or a benchmark.

## Confirmed in the saved public chunks

- **Lagos static scene batching.** `2asxp3jcu780f.js` contains the `MergeStatic` implementation (also saved byte-for-byte as `work/city-map-reference.js`). It waits for scene objects to settle, scans on a 15-frame cadence, and considers explicitly merge-marked descendants. Eligibility excludes instanced/skinned meshes, moving or invisible meshes, interactive meshes, nonzero render order, unsupported material types, and morph targets. It groups compatible objects and builds `InstancedMesh` batches for supported primitive geometry, or merged geometry for other compatible static meshes. Original objects are hidden while merged and restored when movement or membership changes; disposable batch resources are cleaned up. Best pointer: byte offsets 104,900–112,500, especially 105,300–107,500 and 110,000–112,000. Public chunk: [`2asxp3jcu780f.js`](https://lagoslife.eliysites.com/_next/static/chunks/2asxp3jcu780f.js).
- **Abuja repeated geometry batching.** The Abuja scene groups placed primitives by geometry/material class, writes transforms and colors into typed arrays, then renders each compatible group as one `InstancedMesh`. Instance IDs map back to owning lots for clicks. The base geometry/material dictionaries are constructed once in the module. Pointers: `work/map-reference.js` bytes 233–983, 35,000–36,500; instance mesh setup at 30,523–31,210. Public chunk: [`33hpcy7s2rwbe.js`](https://lagoslife.eliysites.com/_next/static/chunks/33hpcy7s2rwbe.js).
- **Abuja scene-wide instancing and memoized data.** Abuja batches map pads, roads, hills, trees, poles, hedges and other repeated items through `InstancedMesh`; the item lists are assembled with `useMemo`. The shared helper writes per-instance matrices and optional colors and recomputes bounds. Pointers: `work/0c4q12y7izpbh.js` bytes 39,960–40,800, 42,274–43,050, and 45,050–47,500. Public chunk: [`0c4q12y7izpbh.js`](https://lagoslife.eliysites.com/_next/static/chunks/0c4q12y7izpbh.js).
- **Reuse and mobile detail controls.** The Lagos scene module reuses a small set of box/cylinder/sphere geometries and caches materials by color/roughness/emissive key. Its building artwork creates core and optional extra details; the map omits extras on phones. Pointers: `work/map-scene-reference.js` bytes 10,329–11,300 and 10,148–10,400. The material cache and primitive geometry declarations cited here are in the map-scene chunk itself, [`2c3zakk_tyr-i.js`](https://lagoslife.eliysites.com/_next/static/chunks/2c3zakk_tyr-i.js); the separate shared-art/batching implementation is in [`33hpcy7s2rwbe.js`](https://lagoslife.eliysites.com/_next/static/chunks/33hpcy7s2rwbe.js).
- **Lazy scene module and model loading.** The route module lazily loads the Lagos scene module through a split chunk; the captured loader references `33hpcy7s2rwbe.js` and `2c3zakk_tyr-i.js` before resolving scene module 67575 (`work/0aebqb-r2y4mc.js`, beginning of file). Separately, the Lagos map wraps car models in `Suspense` with a null fallback (`work/city-map-reference.js` bytes 103,000–104,500). Model assets use `.glb` paths under `/models/world/` (byte 112,000 onward). This confirms deferred code/model paths, not the browser's cache lifetime or transfer savings.
- **Quality and frame scheduling controls.** Both map canvases set `frameloop:"demand"` and pass a configured frame cap. The Lagos canvas reads `sceneDpr` and `sceneAA`, disables shadows on low-power devices unless a screenshot mode is active, and enables antialiasing for screenshot mode or the configured AA preference. It uses a 1024 shadow map in low-power mode and 2048 otherwise, with a fixed shadow-camera volume. Pointers: `work/city-map-reference.js` bytes 148,234–149,000, 150,402–151,200, 152,634–153,500. Abuja has `dpr:S.DPR`, shadows disabled for `LOW_POWER`, and the configured FPS cap at `work/0c4q12y7izpbh.js` bytes 46,866–48,000. Other observed low-power adjustments include billboard canvas resolution/anisotropy and fewer car instances in the Lagos scene.
- **Visibility handling, not a broad frustum-culling claim.** The Lagos batching pass checks the Three.js `visible` flag, while some world labels receive `hideOffscreen`/distance-cull metadata (`work/city-map-reference.js` bytes 151,899–152,400). Several specialized instanced groups explicitly set `frustumCulled=false` (bytes 9,700–10,100 and 98,900–99,100). The source does not support saying the whole map uses aggressive frustum culling.

## Likely effects, with limits

Instancing and static merging reduce the number of individual draw submissions for compatible repeated objects. Reusing geometry and material objects avoids duplicate resource construction. Demand rendering can reduce work while the scene is idle if no component continuously invalidates frames; it does not establish idle CPU/GPU usage by itself. Device-specific DPR, AA, shadows and detail settings expose quality/performance tradeoffs. Lazy chunks/models can defer initial work, while still adding loading cost when the relevant view or model appears.

The JavaScript does not establish FPS, frame-time improvements, memory usage, visual parity, or the number of draw calls saved on a particular device. The saved source has not been benchmarked against the live site.

## Principles for the clone

1. Batch repeated simple props by shared geometry/material, and retain per-instance IDs for interaction.
2. Build a static merge path only for stable, non-interactive meshes; exclude moving, selectable, skinned, and specially rendered objects, and restore source meshes when transforms change.
3. Keep geometry/material resources shared and memoize derived placement arrays; add device-aware detail reductions where they visibly matter.
4. Use demand rendering for a mostly static map, with explicit invalidation during camera movement and animation; offer measured DPR, AA, and shadow tiers.
5. Defer large scene/model modules until needed, then measure both initial load and first-use delay before claiming a speed win.
